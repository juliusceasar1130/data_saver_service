## 什么是事件循环？

### 简单比喻

**事件循环就像一个"任务调度员"**，它负责：
- 管理所有需要等待的任务（如网络请求、文件读写）
- 当某个任务需要等待时，切换到其他任务
- 当任务完成后，继续执行该任务

### 生活中的例子

想象你在餐厅点餐：

**同步方式（阻塞）：**
```
1. 点餐 → 等待厨师做菜（什么都不做，干等）→ 上菜 → 吃
2. 如果厨师很慢，你只能干等，不能做其他事
```

**异步方式（事件循环）：**
```
1. 点餐 → 告诉服务员"做好了叫我" → 去做其他事（看手机、聊天）
2. 服务员（事件循环）监控厨房
3. 菜做好了 → 服务员通知你 → 你回来吃
4. 在等待期间，你可以处理其他事情
```

## 在代码中的体现

### 同步代码（阻塞）

```python
# ❌ 同步方式 - 会阻塞
def sync_example():
    print("1. 开始连接")
    connection = connect_to_server()  # 等待连接，阻塞在这里
    print("2. 连接成功")  # 必须等连接完成才能执行
    data = receive_data()  # 等待数据，又阻塞
    print("3. 收到数据")
    
# 问题：如果连接需要5秒，这5秒内程序什么都不做
```

### 异步代码（事件循环）

```python
# ✅ 异步方式 - 不阻塞
async def async_example():
    print("1. 开始连接")
    connection = await connect_to_server()  # 告诉事件循环"等待连接"
    # 事件循环：连接中，我去处理其他任务...
    print("2. 连接成功")  # 连接完成后，事件循环回来执行这里
    data = await receive_data()  # 告诉事件循环"等待数据"
    # 事件循环：等待数据中，我去处理其他任务...
    print("3. 收到数据")  # 数据到达后，事件循环回来执行这里

# 优势：在等待连接和数据时，可以处理其他任务
```

## 事件循环的工作原理

### 1. 任务队列

事件循环维护一个**任务队列**：

```
任务队列：
┌─────────────────┐
│ 任务1: 连接服务器 │ ← 正在等待网络响应
│ 任务2: 发送心跳   │ ← 等待2秒后执行
│ 任务3: 处理消息   │ ← 等待消息到达
└─────────────────┘
```

### 2. 执行流程

```
开始
  ↓
创建事件循环
  ↓
将 main() 加入任务队列
  ↓
┌─────────────────────────────────┐
│ 事件循环开始工作：                │
│                                  │
│ 1. 检查任务队列                  │
│ 2. 执行可以执行的任务             │
│ 3. 遇到 await → 暂停，等待结果    │
│ 4. 切换到其他可执行的任务         │
│ 5. 结果到达 → 继续执行该任务      │
│ 6. 重复步骤1-5                   │
└─────────────────────────────────┘
  ↓
所有任务完成
  ↓
关闭事件循环
  ↓
结束
```

## 在 WebSocket 客户端中的实际应用

### 代码分析

```python
async def websocket_client(devices):
    # 1. 连接WebSocket（异步操作）
    async with websockets.connect(WS_URL) as websocket:
        # 事件循环：连接中，我可以处理其他任务...
        
        # 2. 订阅设备（异步操作）
        await subscribe_devices(websocket, devices)
        # 事件循环：发送订阅请求，等待响应...
        
        # 3. 启动心跳任务（并发执行）
        heartbeat_task = asyncio.create_task(heartbeat_worker(websocket))
        # 事件循环：创建新任务，两个任务并发执行
        
        # 4. 接收消息循环（异步循环）
        async for message in websocket:
            # 事件循环：等待消息到达...
            await handle_message(message, devices)
            # 事件循环：处理消息时，心跳任务也在运行
```

### 时间线示例

```
时间轴：
0秒  → 开始连接WebSocket
     → 事件循环：连接中，等待...

1秒  → 连接成功
     → 开始订阅设备
     → 事件循环：发送订阅请求，等待...

2秒  → 订阅完成
     → 启动心跳任务
     → 开始接收消息循环
     → 事件循环：同时管理两个任务
        - 任务1：等待WebSocket消息
        - 任务2：每2秒发送心跳

4秒  → 收到消息1
     → 处理消息1（保存数据库）
     → 事件循环：处理中，心跳任务继续运行

6秒  → 发送心跳1
     → 事件循环：心跳发送中，消息接收继续等待

8秒  → 收到消息2
     → 处理消息2
     → 事件循环：处理中...

10秒 → 发送心跳2
     → 继续循环...
```

## 为什么需要事件循环？

### 1. 高效处理I/O操作

```python
# 没有事件循环（同步）：
# 等待网络响应时，CPU空闲，浪费资源

# 有事件循环（异步）：
# 等待网络响应时，可以处理其他任务，充分利用CPU
```

### 2. 并发执行多个任务

```python
# 同时做多件事：
# - 接收WebSocket消息
# - 发送心跳
# - 处理消息
# - 保存数据库

# 事件循环让这些任务"看起来"同时执行
```

### 3. 避免阻塞

```python
# 同步代码：
# 一个慢操作会阻塞整个程序

# 异步代码：
# 慢操作等待时，其他操作继续执行
```

## `asyncio.run()` 做了什么？

```python
asyncio.run(main())
```

等价于：

```python
# 1. 创建新的事件循环
loop = asyncio.new_event_loop()

# 2. 设置为当前线程的事件循环
asyncio.set_event_loop(loop)

try:
    # 3. 运行异步函数，直到完成
    loop.run_until_complete(main())
finally:
    # 4. 清理：取消所有任务
    tasks = asyncio.all_tasks(loop)
    for task in tasks:
        task.cancel()
    
    # 5. 等待所有任务完成
    loop.run_until_complete(asyncio.gather(*tasks, return_exceptions=True))
    
    # 6. 关闭事件循环
    loop.close()
```

## 可视化理解

### 事件循环的工作状态

```
┌─────────────────────────────────────┐
│        事件循环（Event Loop）        │
├─────────────────────────────────────┤
│                                     │
│  任务队列：                          │
│  ┌─────────────────────────────┐   │
│  │ ✓ 连接WebSocket (完成)       │   │
│  │ ✓ 订阅设备 (完成)            │   │
│  │ ⏳ 等待消息 (进行中...)       │   │
│  │ ⏱️  2秒后发送心跳 (等待中)   │   │
│  └─────────────────────────────┘   │
│                                     │
│  当前执行：                          │
│  → 等待WebSocket消息到达            │
│                                     │
│  后台任务：                          │
│  → 心跳定时器：还剩1.5秒            │
│                                     │
└─────────────────────────────────────┘
```

### 消息到达时的处理

```
消息到达
  ↓
事件循环检测到消息
  ↓
暂停等待任务
  ↓
执行处理消息任务
  ↓
保存到数据库（同步操作，快速完成）
  ↓
继续等待下一条消息
  ↓
同时检查心跳任务（时间到了就发送）
```

## 总结

**事件循环就像一个"智能调度员"**：

1. **管理任务**：知道哪些任务在等待，哪些可以执行
2. **切换执行**：当任务需要等待时，切换到其他任务
3. **高效利用**：在等待I/O时，不浪费CPU资源
4. **并发执行**：让多个任务"看起来"同时运行

**`asyncio.run(main())` 的作用**：
- 创建这个"调度员"（事件循环）
- 让它开始工作（运行异步程序）
- 工作完成后清理（关闭事件循环）

这就是为什么异步程序需要 `asyncio.run()` 的原因！
